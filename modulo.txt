Você atuará como arquiteto e implementador full-stack sênior no projeto NFE_WEB.

OBJETIVO DESTA ETAPA
Implementar o módulo fiscal próprio do sistema, com BACKEND + FRONTEND, para que o NFE_WEB passe a ser a fonte de verdade dos dados fiscais necessários à emissão.

A Nuvem Fiscal continuará sendo apenas o provider de emissão.
O sistema interno deve passar a armazenar, editar, validar e servir os dados fiscais que hoje faltam ou estão incompletos para emissão real.

META DE NEGÓCIO
Quero que o sistema tenha estrutura própria para gerenciar:
- empresas emissoras
- clientes/destinatários
- produtos
- dados fiscais dos produtos
- dados fiscais básicos necessários para montar o payload de NF-e
- fluxo visual para cadastro/edição desses dados
- validação para impedir emissão com cadastro incompleto

NÃO quero depender da Nuvem Fiscal para “fornecer os dados fiscais do produto”.
Ela deve apenas emitir a nota a partir de dados que o meu sistema já possui.

CONTEXTO TÉCNICO
- Já existe backend no NFE_WEB
- Já existe provider da Nuvem Fiscal
- Já existe fluxo M2M externo em /v1/external/nfe/issue
- Já existe adaptPayload() e provider selection por FISCAL_PROVIDER
- Já existe apps/api e apps/web no projeto
- O sistema já possui modelagens como Company, Customer, Product, Invoice, etc.
- Já foi identificado que dados como NCM, IBGE emitente/destinatário e CSTs precisam estar realmente no domínio interno

OBJETIVO FUNCIONAL DO MÓDULO
Implementar um módulo próprio no sistema para gerenciar e validar os dados necessários antes da emissão, incluindo:

1. EMPRESA EMISSORA
- dados cadastrais
- CNPJ
- razão social
- endereço completo
- código IBGE do município
- regime tributário / CRT
- status do certificado/configuração, se já houver estrutura

2. CLIENTE / DESTINATÁRIO
- documento (CPF/CNPJ)
- nome/razão social
- email
- telefone, se existir no padrão do sistema
- endereço completo
- código IBGE do município
- classificação mínima necessária para emissão

3. PRODUTO
- SKU/código interno
- descrição
- unidade
- preço base
- NCM
- CFOP padrão, se fizer sentido no domínio
- CSTs necessários:
  - icmsCst
  - pisCst
  - cofinsCst
- demais campos fiscais relevantes que a arquitetura atual já comporte com segurança

4. VALIDAÇÃO DE EMISSÃO
Antes de emitir NF-e, o backend deve validar se:
- empresa possui ibgeCode
- cliente possui ibgeCode
- cada item possui NCM
- cada item possui CSTs exigidos
- referência da transação está presente
- nenhum campo fiscal crítico está faltando silenciosamente

Se faltar algo, erro explícito e claro.
